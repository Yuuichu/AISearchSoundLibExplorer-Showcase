# 架构

统领全局的规则是**单向依赖方向**：

```text
API / CLI  ->  services  ->  repositories / adapters
```

API 路由永不直接接触 SQLite、Qdrant 或 CLAP。正是这条边界让存储层与嵌入层可替换，也正是它让评估门禁有意义：质量可以变化，而接口不变。

## 存储模型

| 层 | 角色 | 权威性 |
|---|---|---|
| **SQLite** | 文件、元数据、任务、反馈、历史、集合 | **唯一事实来源** |
| **Qdrant** | 向量索引（HNSW）与最小化的过滤载荷 | 可替换的索引数据 |
| **源音效库** | 实际的 `.wav` 文件及其内嵌元数据 | **只读，永不修改** |

这一权威顺序带来的结果：

- 重建或迁移向量集合不会丢失用户数据，因为用户数据完全不存在于向量库中。
- 用户元数据与 AI 生成的元数据存放在 SQLite 中，而不是音频文件里。
- 集合名称包含**嵌入模型与预处理身份**，因此更换嵌入会创建新集合，而不是把不兼容的向量混进已有集合。
- 写元数据会在文件旁生成一个独立的 `.sfx.json` 侧车文件（需主动开启，`--confirm`）；源文件内嵌元数据永不被编辑。

## 检索管线

1. **查询解析。** 输入原始文本；可选的 LLM 查询规划（默认关闭）。云查询提供方只收到查询文本。
2. **双路召回。** 两个候选集独立召回——语义（CLAP 文本嵌入对 Qdrant）与元数据/关键词（SQLite）。默认候选预算：各 300。
3. **融合。** 候选使用 **Reciprocal Rank Fusion（k = 60）** 加上精确匹配加分合并，产出单一排序列表。三个面向用户的模式（`keyword`、`semantic`、`hybrid`）决定哪些路径参与贡献。
4. **片段收敛。** 片段级命中被收敛回其父文件，同时保留最佳匹配时间范围——这正是调用方插入一段可用音频片所需的信息。

## 索引管线

- 文件被扫描并计算哈希；哈希阈值区分「低成本变更检测」与「完整重读」。
- **短文件**（低于短音频阈值）：整个文件一个向量。
- **长文件：** 有界的重叠片段——10 秒窗口、5 秒步长、每个文件上限 60 个片段——因此命中可以指向一段长环境声*内部*，而不是整段录音。
- 任务是**可续跑的**：已扫描但尚未嵌入的文件会在下次运行时被安全地重新处理，并每 50 个文件报告一次进度。
- **默认拒绝的嵌入（fail-closed）：** 如果 CLAP 提供方无法加载，索引会拒绝运行。确定性测试提供方仅为开发和 CI 存在（`embedding.allow_deterministic_fallback`），因此生产音效库永远不会被无意义的向量填充。

## 适配器

| 适配器 | 说明 |
|---|---|
| **REAPER** | 基于回环 HTTP 的 ReaImGui 客户端（`docs/reaper-integration.zh-CN.md`） |
| **CLAP** | 生产级文本/音频嵌入提供方 |
| **向量库** | Qdrant（开发时内嵌，大型音效库使用独立 URL） |
| **数据库** | SQLite |

## 接口

- **HTTP API**（FastAPI），在 `/docs` 提供 OpenAPI 描述：检索、相似音频、片段/Range 预览、波形、索引任务、元数据、反馈、历史、集合、UCS 浏览、分层查询与 CSV 导出。
- **CLI**（`python -m sfx`）：`init`、`index`、`search`、`similar`、`benchmark`、`serve`。
- **调试 UI**，与 API 一同在本地提供。
- **REAPER 客户端**，用于 DAW 内操作。

## 校验

- `ruff` 用于静态检查。
- `pytest --cov=sfx` 用于测试套件。
- `scripts/benchmark_scale.py --count 10000` 用于规模基准测试。
- 评估门禁本身：见 `docs/evaluation-gate.zh-CN.md`。
